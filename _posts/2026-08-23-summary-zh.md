## [ShardFlow 通过推测解码在广域网环境下实现 Qwen2.5-7B 每秒 28 个 Token 的推理速度](https://www.reddit.com/r/MachineLearning/comments/1vw5ysj/28_tps_on_qwen257b_across_two_separate_cloud/) ⭐️ 7.0/10

ShardFlow 是一个新型分布式推理框架，它结合了神经推测解码和 CUDA Graphs 技术，在跨高延迟公共广域网连接的 Qwen2.5-7B 模型上实现了每秒 28 个 Token 的吞吐量。通过将草稿生成过程捕获为 CUDA Graph，该系统显著降低了 Python 启动开销，将草稿生成延迟从 112 毫秒降低至 25 毫秒。 这一突破展示了一种实用的架构模式，使开发者能够在地理上分散的云区域部署大语言模型，而无需昂贵的高带宽互连。它有效地缓解了网络瓶颈，使分布式 AI 推理对开发者而言更具可访问性和成本效益。 该框架使用神经草稿模型在每次往返中提交多个 Token，将广域网延迟从“每个 Token 的成本”转化为“每轮的成本”。其他优化措施包括零拷贝 Rust TCP 中继和原地 KV 重绕，以保持与 CUDA Graphs 的兼容性。

reddit · r/MachineLearning · /u/katua_bkl · 8月23日 12:30

## [验证 AI 智能体操作：从“完成”到确认实际状态变更](https://www.reddit.com/r/MachineLearning/comments/1vwa9ap/when_an_ai_agent_says_done_how_do_you_know_it/) ⭐️ 7.0/10

开发者正在试验一个名为“agentuptime”的概念，旨在引入一个独立的验证层，以确认 AI 智能体的副作用（如数据库写入或 API 调用）是否确实在外部系统中发生。该方法将智能体声称的“完成”与任务实际的验证结果分离开来。 这解决了智能体工作流中一个关键的可靠性缺口，即智能体的内部成功信号并不能保证外部系统的一致性。实施此类验证对于将 AI 智能体从实验原型转变为生产级业务自动化系统至关重要。 该提案侧重于为操作生成“回执”，例如在写入后回读记录，或在 API 请求后检查提供程序的状态。它提出了一个技术问题：这是否需要一个专门的架构层，还是现有的可观测性和追踪工具已经足够。

reddit · r/MachineLearning · /u/singed_of_a_down3 · 8月23日 15:32

**背景**: 在分布式系统中，当操作改变了外部系统的状态（例如更新数据库或发送电子邮件）时，就会产生副作用。如果没有幂等性（即多次执行同一操作不会导致额外结果的特性），重试失败的智能体任务可能导致数据损坏或重复操作。目前的可观测性工具可以帮助追踪智能体的尝试过程，但它们往往缺乏确认目标系统最终状态所需的“真实性”验证。
